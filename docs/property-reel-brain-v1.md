# Property Reel Brain v1
Phase 2 deliverable. Chain of cheap planning calls that resolves strategy before any paid generation. Mirrors the D2C Creative Brain: every node has a fixed JSON schema, is shown, is editable, is regenerable alone, has a status, a cost and a lock. Companion files: `brain/schemas.json` (every node output, JSON Schema draft 2020-12) and `brain/rules.json` (constants the gate and the prompts read).

## 0. TLDR

- Ten brain nodes, all text or vision calls, ₹0.2 to ₹0.5 each. Total planning cost per job under ₹5. Nothing paid runs until B8 returns `pass: true`.
- Order: B0 classify photos, B1 listing truth, B2 tier and persona, B3 format, B4 hooks, B5 shot list, B6 copy, B7 music and pacing, B8 pre-flight, then the deterministic assembly recipe. Q1 and Q2 are vision QA nodes on the paid hook path.
- Cheap-first ordering on the hook path: B4 prompt (₹0.2), still (₹4), Q1 still QA (₹0.5), video clip ($0.27), Q2 clip QA (₹0.5). Errors die at the ₹4 layer.
- One job = one listing = three reels. Same B0 to B3, three B4 hook picks, one B5 shot list rendered at three tiers, three B6 copy sets sharing facts, three B7 pacing maps. Only B4 spends money.
- Staleness is by edge: regenerating a node marks its descendants stale with a visible rebuild cost. Editing a field inside a node is a manual regenerate of that node.

Staleness rule: `stale(node) = any parent regenerated after node.generated_at`. The UI shows the rebuild cost as the sum of costs of stale nodes on the path to render. H2 is the only node with a rebuild cost above ₹5, so it is locked by default once Q2 passes.

Lock rule: a locked node is never auto-regenerated by a parent change; the UI shows it as "locked, may be inconsistent" instead.

## 2. Node contracts

Each node below lists purpose, inputs, the system prompt, output schema name (in `schemas.json`), editable fields, and regenerate behaviour. All prompts end with the same instruction: return only JSON matching the schema, no prose.

### B0 Photo classification
Purpose: turn N uploads into a typed asset pool with crop boxes, so nothing downstream ever reasons about raw filenames.
Runs once per photo, in parallel. Output: `PhotoAsset[]`.

System prompt:
```
You classify one real estate listing photo. Return JSON only.
room_class: one of exterior_front, exterior_rear, exterior_side, aerial_34, aerial_topdown, aerial_wide, foyer, hallway, stairs, living, dining, kitchen, primary_bedroom, bedroom, bathroom, half_bath, balcony_view, terrace, garage, pool, gym, clubhouse, garden, floor_plan, site_plan, other.
Score sharpness, exposure and composition 0 to 1 each.
List visible features as short nouns (island, bay window, fireplace, modular kitchen, wardrobe, false ceiling, balcony, solar panels).
flags: people_present, vehicles_present, pets_present, brand_logos_present, staging_suspected (furniture looks rendered: identical pieces, no wear, no shadows), text_overlay_present, watermark_present.
safe_crop_9x16: the x_center and width fraction (0 to 1) of the 9:16 window that keeps the most important feature, and safe_crop_16x9 the same for landscape.
hook_candidate: true only for exterior_front or aerial_34 with the whole building visible and no people.
dedupe_key: a 4 to 6 word description of the space so near-duplicate photos of the same room get the same key.
```
Editable: room_class, features, safe crops, hook_candidate. Regenerate: single photo only.

### B1 Listing truth
Purpose: the only source of claims. Everything in B6 must trace back to a field here. Separates stated facts from photo-derived observations and lists what must never be claimed.
Inputs: facts form (address, locality, city, state or country, price, currency, beds, baths, area value plus area basis, property type, status, year built, possession or open house date, agent name, brokerage, agent handle, agent RERA, project RERA, MLS number, features free text), B0 pool. Output: `ListingTruth`.

System prompt:
```
You build the listing truth record for a property reel. Return JSON only.
Rules:
- facts: copy the form fields exactly. Normalise currency and area units. For market=in the area_basis must be carpet; if the form says super_builtup or saleable, keep the number but set area_basis accordingly and set flags.area_basis_not_carpet=true.
- observed: facts you can see in the photos (from B0 features) that are not on the form. Mark each with the photo id. Never infer size, age, condition or renovation from photos.
- specials: 3 to 5 things that make this listing distinct, each tied to a fact or an observed item by id. No adjectives that describe the buyer.
- never_claim: list every claim that would fail compliance for this market and listing: schools with quality words, safety, family or demographic words, religious proximity, amenities not in the sanctioned plan (in), area on any basis except carpet (in), luxury without stated criteria (in), price drop or sold in N days unless the form supplies the prior price or sale date, any twilight, fireworks, people, vehicles or furniture changes in generated media.
- provable_numbers: numbers the copy may use, each with its source field.
- compliance_context: market, rera_project, rera_agent, rera_portal_url (from rules.json by state), brokerage, mls_number, is_new_launch, is_under_construction, disclosure_required_us (true when market=us), disclosure_required_in (true when any hook is generative).
```
Editable: all. Regenerate: stales B2 to B8.

### B2 Tier and persona
Purpose: decide voice and pacing intent from price and type, without characterising any protected class.
Output: `TierPersona`.

System prompt:
```
Classify the listing. Return JSON only.
price_tier by market using rules.json price_bands (in: budget, mid, premium, luxury by city band; us: entry, mid, upper, luxury by US band).
buyer_intent: one of first_home, upgrade, investor, nri_remote, relocation, downsizer_by_size (size only, never age), rental_yield. Choose by price tier, property type and status. Never use age, family status, religion, nationality or ability.
tone: one of factual_fast, warm_local, premium_calm, investor_numbers.
type_voice: sans_pill or serif_smallcaps (serif for premium and luxury, sans otherwise).
music_energy: low, mid, high.
caption_density: sparse (hook and CTA only), normal (plus two facts), dense (one fact per room).
language: en, or hinglish_overlay when market=in and city in rules.json hinglish_cities and price_tier in [budget, mid].
```
Editable: all. Regenerate: stales B3, B4, B6, B7, B8.

### B3 Format selection
Purpose: pick the reel format for each of the three reels so the three are not the same story.
Output: `FormatPlan` (three entries).

System prompt:
```
Choose three distinct formats from rules.json formats for a three-reel job. Return JSON only.
Reel 1 is always just_listed_reveal unless status is coming_soon, price_improved or sold, in which case use the matching format.
Reel 2 and 3 pick from the remaining formats by score: market_fit x intent_fit x asset_fit, where asset_fit is 0 if the format needs an asset the pool lacks (floor_plan_first needs a floor_plan photo; neighbourhood_tour needs a named place in facts; before_after needs two photos with the same dedupe_key and different dates).
Never pick a format whose compliance_risk for this market is high unless facts explicitly supply what it needs.
For each: format_id, why (one line), required_assets, title_card_system (price_stack, status_card, address_only, search_intent, number_first), tier (fast, medium, slow) so that the three reels use three different tiers.
```
Editable: format_id, tier, title_card_system. Regenerate: stales B4 to B8.

### B4 Hook selection
Purpose: score the hook bank against this listing and produce three fully specified hooks, each with the still prompt, the clip prompt, the engine, the duration, the cost, the disclosure label and the truth-lock plan. This is the only node whose output leads to spend, so it carries the full payload preview.
Runs three times, once per reel, each excluding concepts already picked. Output: `HookPlan`.

System prompt:
```
Select one hook concept for reel {n} from rules.json hook_bank, excluding {already_picked}. Return JSON only.
Score each concept: scroll_stop x engine_survival x compliance_fit x asset_fit x novelty (novelty is 0.6 if the concept was used for this agent in the last 30 days, else 1). asset_fit is 0 if the concept needs aerial_34 and the pool only has exterior_front (drape, block_build, dollhouse need aerial_34 or exterior_front with full building; earth_to_doorstep and sky_drop need aerial_topdown or aerial_wide; blueprint needs exterior_front).
Pick the top score. Then fill:
- source_photo_id: the hook_candidate photo.
- generation_path: one of free_2p5d (no model), still_then_clip (image call then video call), clip_only.
- engine: from rules.json engine_bank by concept default, or the free path.
- aspect: 9x16 always; 16x9 derivative flag.
- still_prompt: for the mid-action frame. Must describe the building only as "the building in the reference image, unchanged", list the theatrical object (drape, helicopter, paper, planet, sketch lines, scaffold), camera, light matching the photo, and the negative list: no people, no vehicles, no extra windows or floors, no text, no logos, no time of day change.
- clip_prompt: the motion from that still to the reveal. State the last frame: "ends on the reference photo exactly".
- duration_s: 6 for Hailuo and LTX, 4 to 8 for Veo Lite. usable_window_s: the 2 to 3 seconds the assembly will cut, chosen from the reveal.
- truth_lock: crossfade_to_source with frames (12 to 20).
- disclosure_label: from rules.json required_overlays by market.
- est_cost: still + clip at the engine rate, plus one retry allowance.
- qa_checks: the list from rules.json qa_reject_list the Q1 and Q2 nodes will run.
- fallback_concept: the next best concept if Q2 fails twice.
```
Editable: concept, engine, prompts, duration, source photo. Regenerate: stales H1, Q1, H2, Q2, B7, B8 for that reel only.

### H1, Q1, H2, Q2 (paid path, per hook)
- H1 image call with `still_prompt` and the source photo as reference. Output: still URL plus cost.
- Q1 vision call: compares the still with the source photo. Prompt: "Count floors, windows on the front face, doors, balconies. Report the roof line shape. List any people, vehicles, text, logos, lights on, sky or time-of-day change. Compare to the reference. Return pass if counts match and the reject list is empty." Output: `QAResult`. Fail regenerates H1 with the Q1 diff appended to the prompt. Two fails escalate to B4 fallback_concept.
- H2 video call with the still as start frame, `clip_prompt`. Output: clip URL plus cost.
- Q2 vision on frames at 25, 50, 75 and 100 percent: same checks plus "does the last frame match the reference within the truth-lock window". Two fails escalate to B4 fallback.

### B5 Shot list
Purpose: map the asset pool to a fixed skeleton, choose one photo per room, assign motion, duration by tier, crop, and a caption slot. Zero cost to render.
Output: `ShotList` with `shots[]` for the shared walkthrough and per-tier durations.

System prompt:
```
Build the shot list from the photo pool and rules.json skeleton. Return JSON only.
- Group photos by dedupe_key. Keep one per group: highest composition score, tie-break on features that appear in listing_truth.specials.
- Skeleton order: exterior_front (title slot), best interior proof shot (kitchen or living or view), then interiors in this order if present: foyer_or_hallway, living, kitchen, dining, primary_bedroom, bathroom, balcony_view, amenities (in only, max 2), then floor_plan, then exterior_return (aerial_34 or exterior_front), then aerial_topdown, aerial_wide, then cta_card.
- Cap interiors at 6. Drop hallway and half_bath first, then duplicates of a room class.
- Motion per shot from rules.json motion_vocabulary by room_class, alternating push and pull so no two consecutive shots share direction.
- Durations from rules.json tiers per slot. Give all three tiers.
- crop_9x16 from B0 safe_crop; if the caption names a feature (bay window, island) make sure the crop keeps that feature.
- caption_slot: none, fact, or title. Only exterior_front, proof, floor_plan and cta_card get title; at most two interiors get fact when caption_density is normal, one per room when dense.
- exclusions: list every photo dropped and why (duplicate, people_present, exterior_rear, low_score, watermark).
```
Editable: order, chosen photo per slot, motion, crop, caption_slot. Regenerate: stales B6, B7, B8.

### B6 Copy
Purpose: every word on screen and in the post, per reel, all traceable to B1.
Runs three times. Output: `CopySet`.

System prompt:
```
Write on-screen and post copy for reel {n} in the {type_voice} voice for market {market}. Return JSON only.
Grammar: every card is a title line (2 to 5 words) plus at most one subtitle line (facts only, under 9 words). Lower third. No exclamation marks. No emoji.
- hook_card: by title_card_system. price_stack: price, then address line, then beds | baths | area with basis label. status_card: status word, address, icon row. number_first: "What {price} gets you in {locality}". search_intent: "Homes for sale in {locality}". address_only: address only.
- proof_card: one special from listing_truth.specials with its source.
- fact_captions: for shots with caption_slot=fact, one title plus subtitle each, from provable_numbers or observed items only.
- floor_plan_card: area with basis label plus one layout fact.
- cta_card: action line from rules.json cta_forms by market, agent line, compliance band lines from rules.json required_overlays (in: RERA project number, portal, agent RERA; us: brokerage, Equal Housing Opportunity, altered-image disclosure with originals_url).
- post_caption: 3 lines: locality keyword phrase with "for sale", the three strongest provable facts, one CTA verb. Then hashtags (3 to 5, locality first). market=in adds the RERA line and a WhatsApp CTA.
- claims_trace: for every number or feature in any card, the listing_truth field id it came from.
Never use any phrase in rules.json banned_phrases for this market. Never characterise the buyer. Never rate a school. Never use luxury for market=in unless listing_truth.facts.luxury_criteria is set.
```
Editable: every string. Regenerate: stales B8 only.

### B7 Music and pacing
Purpose: pick the track family, lock the cut map to the beat grid, and place the hook reveal on the drop.
Inputs: B3 tier, B4 usable window, B5 durations, and the track analysis JSON produced locally by librosa for each track in the licensed library (bpm, beat times, intro_end, drop_time, energy curve). Output: `PacingPlan`.

System prompt:
```
Choose a track and produce the cut map for reel {n}. Return JSON only.
- Pick from the provided track_library entries where energy matches music_energy and tier: fast tier wants bpm 115 to 140 with a drop between 1.8 and 2.4s; medium wants 100 to 130 with a drop between 1.8 and 2.6s or a flat intro; slow wants 80 to 110 flat.
- hook_length_s = drop_time if the track has a drop, else 2.0.
- First cut lands on the drop. Subsequent cuts snap to the nearest beat (fast: every beat, medium: every 4 beats, slow: every 8 beats). Emit cut_times in seconds and the shot id per cut.
- Stutter block: fast tier only, 6 to 10 shots at 0.2s on a fill if the track has one, else skip.
- total_length_s between 13 and 40. If the skeleton overflows, drop from the tail of the interiors, never the hook, the floor plan or the CTA.
- Emit the transition per cut from rules.json transitions, never the same transition twice in a row, whip_blur only on the drop.
```
Editable: track, cut times, transitions. Regenerate: stales B8.

### B8 Pre-flight gate
Purpose: block paid generation and export on failures. Deterministic checks from `rules.json preflight_rules`, plus one text call that scans all B6 strings for banned or coded phrases beyond exact matches.
Output: `PreflightResult`. `pass` is true only when there are zero BLOCK results. WARN results are listed with an override checkbox that records who overrode and when.

The gate runs twice: once before H1 (hook path checks only) and once before export (everything).

### A Assembly recipe
Deterministic. Merges B4 (clip URL and usable window), B5 (shots, crops, motion), B6 (cards), B7 (cut map, transitions, track) into a render manifest the ffmpeg worker executes: `AssemblyRecipe`. Contains the 9:16 master and the 16:9 derivative timeline, overlay PNG sequences (type is rendered by canvas to PNG, never by drawtext), the truth-lock crossfade, the disclosure overlay window, and the CTA band. Zero model cost.

## 3. Three-reel job logic

| Shared once | Per reel |
|---|---|
| B0, B1, B2 | B3 entry n, B4 hook n, B6 copy n, B7 pacing n |
| B5 shot list (three tier variants emitted in one call) | Tier n from B3 |
| Q1 and Q2 prompts | H1, Q1, H2, Q2 per hook |

Variation guarantee: three different hook concepts, three different tiers, three different transition families, at least two different title-card systems. The gate warns if any two reels share hook concept plus tier.

Budget line at job level: sum of est_cost across three B4 nodes plus ₹5 planning plus ₹27 QA. Target under $3. The header spend meter reads the ledger, not the estimates.

---

## 4. Ledger entries
Every node call writes `{job_id, reel_n, node, model, input_tokens, output_tokens, unit_cost, cost_inr, cost_usd, started_at, ended_at, status, parent_versions[]}`. Regenerations append, never overwrite. The spend meter is the sum where status=succeeded. Estimates are shown greyed until the entry lands.

## 5. Model routing defaults
| Role | Default | Fallback |
|---|---|---|
| Text nodes B1 to B8 | Gemini 2.5 Flash-Lite via the existing Vertex proxy | GPT-4o-mini |
| Vision B0, Q1, Q2 | Gemini 2.5 Flash | GPT-4o-mini vision |
| Still H1 | Nano Banana via Vertex (already proxied) | fal Seedream |
| Clip H2 | Hailuo 02 Standard on fal for drape, drop, block_build, earth_to_doorstep. Veo 3.1 Lite via Vertex for dollhouse and pop-up. LTX-2 Fast for drafts only | Kling 2.5 Turbo |
| Free path | ffmpeg plus canvas PNG sequences for blueprint, dollhouse, sky_drop 2.5D, pop-up | none |

All prompts use `response_mime_type: application/json` with the schema attached where the model supports it, and a strict JSON repair pass (strip fences, retry once) where it does not.

## 6. What Claude Code builds from this
1. `brain/schemas.json` and `brain/rules.json` as data, loaded at boot, editable from the dashboard's rules tab.
2. One `runNode(nodeId, jobId, reelN)` function that loads inputs by edge, renders the prompt from the template, calls the routed model, validates against the schema, writes the ledger, and marks descendants stale.
3. The gate as a pure function over the node outputs plus `rules.json`.
4. The assembly recipe as a pure function; the ffmpeg worker consumes it.
5. The track library analysed once with librosa into `tracks/*.json`.
